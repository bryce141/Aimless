GUIDELINE 2.1(a) — error message after tapping Generate

We reproduced this and found the cause. It is not specific to iPad.

Aimless requests routes from a third-party routing service that enforces a
limit of 40 requests per minute shared across all users of the app. A single
tap of Generate costs roughly 18 of those requests, because the app requests
twelve candidate loops and then verifies the most promising ones. Three
generates within one minute therefore succeed, and a fourth is throttled by
the routing service. When that happens the app correctly reports that it could
not build a route, which is the error message you saw.

Testing the app repeatedly, as a reviewer naturally would, reaches that limit
in normal use. We consider this a real defect rather than expected behavior.

The fix is deployed and live. Route responses are now cached, which is
effective here because identical requests return identical routes. Measured
before and after, performing four generates in succession from one location:

  Before:  48 requests to the routing service, 8 of them throttled
  After:   23 requests to the routing service, none throttled

We verified this against the live service using coordinates in Cupertino,
California, and the error no longer occurs.

Please note this fix is entirely server-side, in the routing service the app
communicates with. It required no change to the app binary, so build 1.0 (3)
currently under review is already corrected and needs no resubmission. Simply
testing the existing build again will show the corrected behavior.
